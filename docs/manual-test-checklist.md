# Checklist ทดสอบด้วยมือ — ก่อนเริ่ม Phase 2

เอกสารนี้คือสิ่งที่ **ระบบอัตโนมัติทดสอบแทนไม่ได้** เพราะ CI รันแบบ headless บน Linux
ซึ่งไม่มีคลิปบอร์ดระดับระบบปฏิบัติการ และ Playwright WebKit ก็ไม่ใช่ Safari จริง

> ⚠️ **ข้อ A1–A3 สำคัญที่สุด** ถ้าสามข้อนี้ไม่ผ่าน ลำดับความสำคัญของ Phase 2 ต้องเปลี่ยนทั้งหมด
> เพราะการคัดลอกคือทางออกหลักของผลิตภัณฑ์

## เตรียมตัว

```bash
npm install          # ถ้ายังไม่ได้ลง
npm run dev          # เปิด http://localhost:5173
```

หรือทดสอบเวอร์ชัน production จริง (แนะนำสำหรับ A1–A3 เพราะใกล้ของจริงกว่า):

```bash
npm run build && npx vite preview --port 4173
```

**หมายเหตุ:** Clipboard API ต้องอยู่ใน secure context — `localhost` นับเป็น secure แล้ว ใช้ได้เลย
แต่ถ้าเปิดผ่าน IP ของเครื่องอื่น (เช่น `192.168.x.x`) จะใช้ไม่ได้ ต้องมี HTTPS

## A. คลิปบอร์ด — สำคัญที่สุด

### A1 · คัดลอกแล้ววางในแอปปลายทางจริง
วางสกรีนช็อต 3 รูป → กด **Copy** → สลับไปแอปอื่น → Ctrl/Cmd+V

| แอปปลายทาง | Chrome/Edge | Safari | Firefox | หมายเหตุ |
|---|---|---|---|---|
| Slack | ☐ | ☐ | ☐ | |
| LINE (desktop) | ☐ | ☐ | ☐ | |
| Jira / คอมเมนต์ | ☐ | ☐ | ☐ | |
| Gmail | ☐ | ☐ | ☐ | |
| Microsoft Word | ☐ | ☐ | ☐ | |
| Google Docs | ☐ | ☐ | ☐ | |
| Discord | ☐ | ☐ | ☐ | |
| Notion | ☐ | ☐ | ☐ | |

**ผ่านเมื่อ:** ภาพขึ้นครบ ไม่ใช่ไฟล์แนบเปล่า ๆ · ความคมชัดเป็น 2x (ซูมแล้วยังคม) · พื้นหลังถูกต้อง

### A2 · Safari จริง และ Firefox จริง
ADR-003 ยืนยันการคัดลอกได้เฉพาะ Chromium เท่านั้น สองเบราว์เซอร์นี้ยัง **ไม่รู้ผล**

- ☐ Safari (macOS) — กด Copy แล้ววางได้จริงหรือไม่
- ☐ Firefox — กด Copy แล้ววางได้จริงหรือไม่
- ☐ ถ้าคัดลอกไม่ได้ → แอปต้อง **ดาวน์โหลดไฟล์ให้อัตโนมัติ** พร้อม toast อธิบาย ไม่ใช่เงียบหรือค้าง

**ถ้า Safari/Firefox คัดลอกไม่ได้จริง** → ต้องกลับไปแก้ [ADR-003](decisions/ADR-003-clipboard.md)
และพิจารณาเปลี่ยนปุ่มหลักเป็น Download บนเบราว์เซอร์เหล่านั้น

### A3 · วางรูปเข้ามาจากคลิปบอร์ดของ OS
นี่คือทางเข้าหลักของผลิตภัณฑ์ ต้องทำงานไร้รอยต่อ

- ☐ Windows: `Win+Shift+S` แคปหน้าจอ → Ctrl+V ในแอป
- ☐ Windows: Snipping Tool แบบเปิดหน้าต่าง → Copy → Ctrl+V
- ☐ macOS: `Cmd+Ctrl+Shift+4` (แคปลงคลิปบอร์ด) → Cmd+V
- ☐ macOS: `Cmd+Shift+4` (แคปลงไฟล์) → ลากไฟล์จาก Desktop เข้ามา
- ☐ คลิกขวารูปในเว็บ → "คัดลอกรูปภาพ" → Ctrl+V
- ☐ คัดลอกรูปจาก LINE / Slack → Ctrl+V
- ☐ วางข้อความธรรมดา (ไม่ใช่รูป) → ต้องไม่พัง ไม่ขึ้น error น่ากลัว

## B. Drag & drop จาก OS จริง

- ☐ ลากไฟล์เดียวจาก File Explorer / Finder
- ☐ ลากหลายไฟล์พร้อมกัน (5+ ไฟล์)
- ☐ ลากจาก Desktop
- ☐ ลากรูปจากแท็บเบราว์เซอร์อื่นเข้ามาโดยตรง
- ☐ ระหว่างลาก overlay ต้องขึ้นทั้งหน้าจอ และบอกจำนวนไฟล์ถูกต้อง
- ☐ ลากออกนอกหน้าต่างแล้วกลับเข้ามา — overlay ต้องไม่ค้าง
- ☐ ลากไฟล์ปน (รูป + PDF + SVG) → รับเฉพาะรูป ปฏิเสธที่เหลือทีละไฟล์พร้อมบอกชื่อ

## C. คุณภาพผลลัพธ์ (ตาคน ไม่ใช่เทสต์)

ใช้สกรีนช็อตงานจริง ไม่ใช่ภาพ gradient สังเคราะห์แบบใน CI

- ☐ สกรีนช็อตแชท LINE/Messenger แนวตั้ง 3–4 ใบ → เรียงเป็นแถวเดียวอ่านง่าย
- ☐ สกรีนช็อต desktop เต็มจอ 3 ใบ → เรียงลงล่าง แต่ละใบยังอ่านตัวหนังสือออก
- ☐ before/after 2 ใบ → เข้าโหมดเทียบคู่ สูงเท่ากัน เทียบง่าย
- ☐ error dialog เล็ก ๆ (~400px) → **ไม่ถูกยืดจนเบลอ**
- ☐ สกรีนช็อตเต็มหน้า (full-page ยาวมาก) → ไม่ทำให้ board พัง
- ☐ PNG พื้นหลังโปร่งใส → export แล้วยังโปร่งใสจริง (ลองวางบนพื้นหลังสีอื่น)
- ☐ โหมด Steps → เลข 1,2,3 อ่านออก ขนาดพอเหมาะ ไม่ทับรูป
- ☐ พื้นหลังดำ + สไตล์ Soft → ดูดี ไม่ใช่ดูสกปรก
- ☐ ผลลัพธ์โดยรวม **"ส่งให้หัวหน้าได้โดยไม่เขิน"** หรือยัง

## D. Time-To-Copy กับคนจริง

ตัวชี้วัดหลักของผลิตภัณฑ์ ระบบอัตโนมัติวัดได้แค่ latency ของแอป (69–210 ms) ไม่ใช่เวลาของคน

**วิธีทำ:** หาคน **3 คนที่ไม่เคยเห็นแอป** บอกแค่ว่า *"เอาสกรีนช็อต 3 รูปนี้รวมเป็นภาพเดียวแล้วส่งมาให้หน่อย"*
แล้ว **ห้ามอธิบายอะไรเพิ่ม** จับเวลาตั้งแต่เปิดเว็บจนคัดลอกสำเร็จ

| คน | เวลา (วินาที) | สะดุดตรงไหน | ถามอะไร |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

- ☐ เวลามัธยฐาน **< 20 วินาที**
- ☐ ไม่มีใครต้องถามว่า "ต้องทำอะไรต่อ" ในหน้าแรก
- ☐ ทุกคนหาปุ่ม Copy เจอเองโดยไม่ต้องบอก

**สิ่งที่ต้องจดคือจุดที่เขา "ลังเล"** ไม่ใช่แค่ตัวเลข — จุดลังเลคืองาน Phase 2

## E. ความทนทานและ edge case

- ☐ วางรูป 20+ ใบ → UI ไม่ค้าง มีตัวบอกความคืบหน้า
- ☐ ไฟล์ HEIC จาก iPhone → ขึ้นข้อความบอกชัดเจน ไม่ใช่พังเงียบ
- ☐ ไฟล์เสีย (เปลี่ยนนามสกุล .txt เป็น .png) → ปฏิเสธพร้อมบอกเหตุผล
- ☐ ไฟล์ใหญ่เกิน 50 MB → ปฏิเสธพร้อมบอกเหตุผล
- ☐ กด Copy รัว ๆ 5 ครั้ง → ไม่พัง
- ☐ ย่อ/ขยายหน้าต่างเบราว์เซอร์ → board ปรับขนาดตามได้ถูกต้อง
- ☐ เปลี่ยนธีมระบบเป็น dark → UI เปลี่ยนตาม แต่ **พื้นหลังของ board ไม่เปลี่ยน**
- ☐ ปิดแท็บแล้วเปิดใหม่ → งานหาย (**ถูกต้องตามที่ตั้งใจใน Phase 1** — autosave อยู่ Phase 2)

## F. ยืนยันคำสัญญา privacy ด้วยตาตัวเอง

- ☐ เปิด DevTools → แท็บ Network → ทำงานครบวงจร → **ไม่มีคำขอใดนอกจากไฟล์ของแอปเอง**
- ☐ ตัดอินเทอร์เน็ต (ปิด WiFi) แล้ว refresh → ยังใช้งานได้หรือไม่
      *(คาดว่ายังไม่ได้ — PWA/offline อยู่ Phase 6 · ถ้าอยากได้เร็วกว่านั้นบอกได้)*

## บันทึกผล

เมื่อทดสอบเสร็จ ให้จดสามอย่างนี้ไว้แล้วส่งกลับมา:

1. **ข้อไหนไม่ผ่าน** และเกิดอะไรขึ้นจริง ๆ (ยิ่งละเอียดยิ่งดี)
2. **จุดที่ผู้ใช้ลังเล** จากข้อ D — สำคัญกว่าตัวเลขเวลา
3. **ความรู้สึกรวม** ต่อคุณภาพของภาพที่ได้จากข้อ C

จากนั้นผมจะปรับลำดับงาน Phase 2 ตามผลจริง แทนที่จะทำตามแผนที่เดาไว้ล่วงหน้า
