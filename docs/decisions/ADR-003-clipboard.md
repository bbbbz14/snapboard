# ADR-003 — กลยุทธ์ clipboard: คัดลอกเป็นทางหลัก ดาวน์โหลดเป็นทางรองที่มองเห็นเสมอ

- สถานะ: **ตัดสินใจแล้ว** (Phase 0) · ต้อง **ยืนยันด้วยมือบนเบราว์เซอร์จริง** ก่อนปิด Phase 3

## การวัดจริง (spike S1, headless Playwright)

| การตรวจสอบ | chromium | firefox | webkit |
|---|---|---|---|
| `ClipboardItem` มีอยู่ | ✅ | ✅ | ✅ |
| `ClipboardItem.supports('image/png')` | ✅ | ✅ | ✅ |
| `navigator.clipboard.write()` resolve สำเร็จ | ✅ | ✅ | ✅ |
| อ่านกลับมาแล้วเจอ image/png | ✅ | ❌ (คลิปบอร์ดว่าง) | ❌ (ถูกปฏิเสธสิทธิ์) |
| **คัดลอกแล้ววางจริง → ได้รูป** | ✅ **1 รูป** | ❌ **0 รูป** | ❌ **0 รูป** |

## ข้อค้นพบที่สำคัญที่สุด
> **`write()` ที่ resolve สำเร็จ ไม่ใช่หลักฐานว่าข้อมูลลงคลิปบอร์ดจริง**

Firefox resolve promise ให้เรียบร้อย แต่คลิปบอร์ดว่างเปล่า
ดังนั้น **ห้ามใช้ผลลัพธ์ของ `write()` เป็นเงื่อนไขในการแสดงข้อความ "คัดลอกแล้ว"** โดยลำพัง

## ข้อจำกัดของการวัดครั้งนี้ (ต้องระบุอย่างตรงไปตรงมา)
สภาพแวดล้อมนี้เป็น **headless Linux** ซึ่งไม่มีคลิปบอร์ดระดับระบบปฏิบัติการจริง
และ Playwright WebKit **ไม่ใช่ Safari จริง**
ดังนั้นผลของ firefox/webkit ข้างต้น **สรุปไม่ได้ว่าเบราว์เซอร์จริงทำงานไม่ได้** — สรุปได้เพียงว่า **ยืนยันไม่ได้ในสภาพแวดล้อมนี้**
ต้องทดสอบด้วยมือบน Safari จริงและ Firefox จริงก่อนปิด Phase 3

## การตัดสินใจ
1. ใช้รูปแบบ **Promise-in-ClipboardItem** เสมอ:
   `new ClipboardItem({ 'image/png': renderPromise })` — ห้าม `await` ก่อนสร้าง ClipboardItem เพื่อรักษา user activation
2. เรียกจากภายใน user gesture เท่านั้น (click / keydown) ห้ามอยู่ใน `setTimeout`
3. **ปุ่มดาวน์โหลดต้องมองเห็นได้เสมอ** ข้าง ๆ ปุ่มคัดลอก ไม่ใช่ซ่อนไว้ในเมนู — เพราะเราตรวจจับความล้มเหลวแบบเงียบไม่ได้
4. บนเบราว์เซอร์ที่ยังไม่ได้ยืนยัน ให้ toast หลังคัดลอกบอกว่า *"Copied. If paste doesn't work, use Download."*
5. ถ้า `ClipboardItem` ไม่มีหรือ throw → สลับเป็นดาวน์โหลดทันทีโดยอัตโนมัติ ไม่ต้องถาม

## ผลที่ตามมา
- ผู้ใช้ Chromium/Edge (กลุ่มหลัก) ได้ประสบการณ์คัดลอกที่ยืนยันแล้วว่าใช้ได้จริง
- ผู้ใช้เบราว์เซอร์อื่นไม่มีทางเจอทางตัน เพราะดาวน์โหลดอยู่ตรงนั้นเสมอ
