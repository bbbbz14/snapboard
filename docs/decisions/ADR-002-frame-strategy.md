# ADR-002 — วาดด้วย tile cache ต่อ node ไม่ใช่วาด scene ใหม่ทั้งเฟรม

- สถานะ: **ตัดสินใจแล้ว** (Phase 0, 2026-09-10)

## บริบท
สไตล์ภาพของผลิตภัณฑ์ (ขอบมน + เงานุ่ม) คือสิ่งที่ทำให้ผลลัพธ์ "ดูโปร"
แต่ต้องรู้ก่อนว่ามันแพงแค่ไหน ก่อนจะออกแบบ loop การวาด

## การวัดจริง (spike S4c — 9 รูป, canvas 1268×878, บังคับ flush ด้วย getImageData ก่อนอ่านนาฬิกา)

| กลยุทธ์การวาด | chromium | firefox | webkit |
|---|---|---|---|
| สี่เหลี่ยมธรรมดา | 3.2 ms | 3 ms | 2 ms |
| + ขอบมน | 3.5 ms | 3 ms | 2 ms |
| + ขอบมน + **เงา** | **12.5 ms** | **21 ms** | **23 ms** |
| ต้นทุนเฉพาะเงา | 9 ms | 18 ms | 21 ms |
| **pre-render เป็น tile แล้ว drawImage** | **0.7 ms** | **1 ms** | **1 ms** |
| เร็วขึ้น | **17.9×** | **21×** | **23×** |

## ข้อค้นพบ
1. **`shadowBlur` คือคอขวด กินเวลา 72–91% ของทั้งเฟรม** — ถ้าวาด scene ใหม่ทุกเฟรมตอนลาก จะได้แค่ ~43fps บน WebKit ตั้งแต่มีรูปแค่ 9 รูป
2. ขอบมนแทบไม่มีต้นทุน
3. การ pre-render แต่ละ node ลง tile แล้ว `drawImage` ทำให้เฟรมถูกลงเกือบ 20 เท่า

## การตัดสินใจ
- แต่ละ image node มี **tile cache** ของตัวเอง (offscreen canvas ที่อบเงา+ขอบมนไว้แล้ว)
- loop การวาด = ล้างพื้นหลัง + `drawImage` ของ tile ตามลำดับ z
- invalidate tile เฉพาะเมื่อ **ขนาด / crop / สไตล์ / bitmap** ของ node นั้นเปลี่ยน — **การย้ายตำแหน่งไม่ต้อง invalidate**
- แบ่ง canvas 2 ชั้น: ชั้นเนื้อหา และชั้น interaction (handle, guide, marquee) ที่วาดใหม่ได้ถูก ๆ
- ตอน export ปิด tile cache แล้วเรียก `renderScene` ตรง ๆ ที่ scale ที่ต้องการ (คุณภาพเต็ม ไม่ขยายจาก tile)

## หมายเหตุด้านวิธีวัด
WebKit รายงาน 0 ms ในการวัดรอบแรก เพราะคำสั่ง canvas rasterize แบบ asynchronous
**การจับเวลา canvas ต้องบังคับ flush** (อ่าน `getImageData` 1 พิกเซล) ก่อนอ่านนาฬิกาเสมอ
กฎนี้ต้องใช้กับการวัดประสิทธิภาพทุกครั้งในโปรเจกต์นี้
