# ADR-007 — ยอมรับความต่างระดับพิกเซลขอบบน Firefox จาก tile cache

- สถานะ: **ตัดสินใจแล้ว** (Phase 1, 2026-09-10)

## บริบท
ADR-002 กำหนดให้ preview ใช้ tile cache (เร็วขึ้น 18–23 เท่า) ส่วน export วาดตรงเพื่อคุณภาพเต็ม
จึงต้องพิสูจน์ว่าสองเส้นทางให้ผลเหมือนกัน

## สิ่งที่การทดสอบจับได้ (และเป็นเหตุผลที่การทดสอบนี้คุ้มค่า)
ระหว่างทำ Phase 1 การทดสอบ parity จับ **บั๊กจริง** ได้หนึ่งข้อ:

> `exportBoard` สร้าง context ด้วย `{ alpha: false }` เมื่อพื้นหลังทึบ
> ทำให้ Chromium สลับไปใช้ **subpixel antialiasing** กับตัวอักษร
> ตัวเลขใน badge ที่ export ต่างจากที่เห็นบนจอ **สูงสุด 100 ระดับต่อ channel**

แก้แล้วโดยให้ทั้งสองเส้นทางใช้ค่า alpha เดียวกัน — นี่คือความเสี่ยง R1 ตัวเป็น ๆ
และจะยิ่งสำคัญขึ้นมากใน Phase 4 ที่มีเครื่องมือข้อความ

## ความต่างที่เหลืออยู่
| เอนจิน | ค่าผิดพลาดสูงสุด/channel | พิกเซลที่ต่าง |
|---|---|---|
| Chromium | 0–1 | 0 |
| WebKit | 0–1 | 0 |
| **Firefox** | **8–21** | **3–84 จุด (~0.006%)** |

**สาเหตุ:** tile มีขอบมนและเงาที่เป็น partial alpha การ composite ผ่าน tile จึงผสม alpha **สองครั้ง**
ขณะที่ export ผสมครั้งเดียว Chromium/WebKit ปัดเศษจนหายไป Firefox ไม่

## การตัดสินใจ
ยอมรับ โดยตั้ง tolerance **แยกตามเอนจิน**: Chromium/WebKit ≤ 2 · Firefox ≤ 24
และทุกเอนจินต้องกระทบพิกเซลไม่เกิน 0.02% ของภาพ

**เหตุผล:**
1. ความต่างอยู่เฉพาะพิกเซล antialiasing ที่มุมโค้ง — มองด้วยตาไม่เห็น
2. **ไฟล์ที่ export คือฝั่งที่ถูกต้อง** (วาดตรงไม่ผ่าน tile) ส่วน preview คือฝั่งที่คลาดเล็กน้อย
   ทิศทางของความคลาดจึงปลอดภัย: ผู้ใช้ได้ไฟล์ที่ดีเท่าหรือดีกว่าที่เห็น
3. การกำจัดให้เป็น 0 ต้องอบสีพื้นหลังลงใน tile ซึ่งจะพังเมื่อวัตถุซ้อนกัน (Phase 2 โหมด free)

**ตั้งค่าเข้มที่สุดเท่าที่เอนจินยอม** ไม่ตั้งหลวมเท่ากันหมด เพื่อให้ยังจับ regression จริงได้ —
บั๊ก alpha/antialiasing ข้างต้นมีค่าผิดพลาด 100 ซึ่งเกิน tolerance ของทุกเอนจินอยู่ดี

## ทบทวนเมื่อไร
ถ้า Phase 4 เพิ่มเครื่องมือข้อความแล้วพบว่า Firefox คลาดเกิน 24 → ต้องกลับมาพิจารณา tile แบบทึบ
