# ADR-005 — จำกัดขนาด export และลด scale อัตโนมัติเมื่อเกินขีดจำกัดของเบราว์เซอร์

- สถานะ: **ตัดสินใจแล้ว** (Phase 0)

## การวัดจริง (spike S3 — binary search หาขนาด canvas ที่ยังอ่าน pixel กลับมาได้)

| | chromium | firefox | webkit |
|---|---|---|---|
| จัตุรัสใหญ่สุด | 16384 px | 23168 px | 16384 px |
| พื้นที่สูงสุด | 268 MP | 537 MP | 268 MP |
| ความสูงสูงสุดที่ความกว้าง 4000 | 65472 | 65472 | 65536 |
| ด้านเดียวยาวสุด | 65472 | 65472 | 131072 |

## ข้อค้นพบ
1. ข้อจำกัดจริงคือ **พื้นที่รวม (area)** ไม่ใช่ความยาวด้าน — canvas ยาว 65000×4000 ทำได้ แต่ 20000×20000 ทำไม่ได้
2. **ตัวเลขเหล่านี้มาจาก desktop Linux เท่านั้น** — iOS Safari ต่ำกว่านี้มาก (มักจำกัดที่ ~16–50 MP ขึ้นกับ RAM ของเครื่อง) **ต้องวัดซ้ำบนอุปกรณ์จริง**

## การตัดสินใจ
- ก่อน export คำนวณ `bounds × scale` แล้วตรวจกับงบพื้นที่ปลอดภัย (เริ่มที่ **100 MP** ซึ่งต่ำกว่าค่าที่วัดได้ทั้งหมดอย่างมีระยะปลอดภัย)
- ถ้าเกิน → **ลด scale ลงอัตโนมัติ** (3x → 2x → 1x) และบอกผู้ใช้ตรง ๆ ว่าลดเพราะอะไร ไม่ใช่ปล่อยให้ crash เงียบ ๆ
- แสดงขนาดผลลัพธ์ (พิกเซล + MB โดยประมาณ) ในเมนู export **ก่อน** ผู้ใช้กด
- ถ้าเกิน 100 MP แม้ที่ 1x → เสนอ JPG แทน PNG และเตือนว่าภาพใหญ่มาก
- จำกัดรูปขาเข้าที่ 100 MP และ 50 MB ต่อไฟล์ เพื่อกัน decompression bomb (ดูข้อ 10 ของแผน)
